# pic2color4px 技術メモ

## これは何か（位置づけ）

pic2gray4px のセル方式をカラーに拡張した変換ツール。**圧縮技術ではなく、表示能力の限られたデバイス（MSX系の8色、カラー電子ペーパー、T02等の感熱プリンター）向けの変換技術**である。汎用圧縮として JPEG と競うものではない（この結論は、後述の pic2codec 実験で実測により確認した）。

## アルゴリズム

入力画像を 2×2 ピクセルのセルに分割し、チャンネル（R/G/B）ごとに次を行う。

1. **密度（カウント）の決定**：セルの平均色を、セルレベルの誤差拡散で 0〜4 の整数カウントに量子化する。拡散の重みは Floyd–Steinberg の 7/16, 3/16, 5/16, 1/16 をピクセル格子からセル格子へ移植したもの。
2. **配置の最適化**：カウントが決まったセルの中でのドット配置（カウント k に対し候補は最大4通り）を、3チャンネル合同で最適化する。評価は知覚空間：出力と原画をそれぞれガウスぼかし（σ=1.1, 9×9）したものの残差ノルム。座標降下法で、残差は増分更新する。初期配置・走査順・パス数（最大8、変化ゼロで早期終了）は固定で、**決定的**に動作する（同じ入力→同じ出力）。

出力は R/G/B オン・オフの 8 色ちょうどになる。知覚上は 5段階×3チャンネル＝125 通りの見かけの色が得られる。

Rust 版と Python 版は同じアルゴリズムで、たね子 384×384 での知覚 RMSE（ぼかし比較）は両者とも 5.68 と一致した。処理時間は Rust 版 約0.9秒、Python 版 約177秒。

## 測定で分かっていること（正直な限界も含む）

- **内容依存性**：なめらかな CG・イラストでは本方式が映える。毛並みのような高周波の写真テクスチャでは、チャンネル別 Floyd–Steinberg と知覚 RMSE がほぼ互角になる（MSX2 256×212 の猫写真で FS 11.2 vs 本方式 11.5、初期の簡易測定）。
- **デバイス前提の優位**：同サイズの JPEG を復号してからチャンネル別ディザで8色化する経路と比較すると、本方式が知覚 RMSE で約15〜20%良い（pic2codec 実験、2026-11-06）。JPEG の圧縮誤差とディザ誤差を二重に払わないため。
- **守備範囲外**：小さい文字、1ドットの線、QR コード、ドット絵そのもの。これらは画素そのものが意味を持つため、ぼかして知覚一致を狙う本方式の対象ではない。

## pic2codec 実験（関連）

「種（セル平均色や密度カウント）だけを保存し、読み込み時に最適化を再実行して画像を再生成する」形式を Rust で実装・測定した（実験用プロトタイプ、別管理）。要点：

- 再生成は実用的（384×384 で約1秒）。決定的再実行により再生が成立する
- 品質の天井は種の精度ではなく表現形式（8色＋2×2セル）が決めるため、種は強く圧縮できる（平均色を JPEG q90 で保存し合計 11,253 B / 原画比 約1/16 でも RMSE は 5.82→6.71）
- フルカラー fidelity では全サイズ帯で JPEG に劣る。**結論：これは圧縮技術ではなく、低表示能力デバイス向けの変換技術**

## 実装

- `src/main.rs`：Rust CLI 本体。引数：入力ファイル、`--width N`、`-o 出力`、`--force`
- `python/pic2color4px.py`：Python 試作（合同最適化の原型）。MSX2 256×212 へのフィット処理を含む
